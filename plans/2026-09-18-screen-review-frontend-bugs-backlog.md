# Ревью экранов — бэклог фронтенд-багов

Идём по экранам приложения по очереди (пользователь называет экран, разбираем
функционал). Решение (2026-09-18): бэкенд-баги чиним сразу по ходу разбора,
фронтенд-баги/недочёты — только записываем сюда, чтобы разобрать и
исправить отдельным заходом позже, не трогаем фронт походя.

Формат записи: экран → что не так → где в коде → почему не критично прямо
сейчас (если фикс отложен по причине, а не просто "потом").

Найдено и исправлено **2 серьёзных бэк-бага** в `history/detail/`: (1) **IDOR** — `select_mobile_history_details()` искала запись только по `id`, без проверки владения; любой клиент мог прочитать чужую детализацию (для переводов — имя и телефон получателя), подбирая `id`; подтверждено живым тестом (чужая "секретная" запись отдалась целиком). Фикс — проверка `balance_id` (та же граница, что уже использует список). (2) **Краш HTTP 500 на КАЖДОМ Топаз-наливе** — `check_id` для Топаз-наливов это UUID заказа, а старый код искал его в легаси-таблице чеков (`cheks`/`chek_sostav`), ничего не находил и падал на `DivisionByZeroError` (PHP 8) при делении `sale/count`. Подтверждено живым curl на реальной записи (было 500 → стало 200 с верными данными АИ-95/2.51л/95₽). Оба фикса задеплоены, смёржены. Заодно закрыт старый открытый вопрос из памяти `balance-history-clients-transactions-rewrite` — «почему `mobile_history` пуст по переводам» оказалось не багом (см. карту эндпоинтов). Фронтенд-находка в бэклог: `GetHistoryPieChart.tsx` определяет цвет/подпись для `PAY_BALANCE` в донат-чарте, но бэк (`select_mobile_history_chart`) намеренно исключает `type=1` из выборки целиком (`WHERE ... type != 1`) — сегмент «Пополнение баланса» физически никогда не появится на графике. Не трогал — неочевидно, баг это или осознанное решение (type=1 объединяет разнородные события: пополнения, бонусы, входящие переводы), нужно решение продукта.

## Home

- **`ConvertBonusToBalance.tsx`** (`src/features/Home/ConvertBonusToBalance/ui/ConvertBonusToBalance.tsx:67`) —
  `if (bonusBalance <= 0) return null` пропускает `bonusBalance === undefined`
  (сравнение с `undefined` в JS всегда `false`, кнопка не скрывается).
  Раньше это реально стреляло из-за бага на бэке (`/home/` не отдавал
  `bonus_balance`, см. ниже) — сам баг на бэке уже исправлен
  (`azerpetrol-topaz-server`, коммит `0a12d78`, задеплоено и подтверждено
  вживую 2026-09-18), поэтому `undefined` в этом месте с высокой вероятностью
  больше не возникает. Не критично прямо сейчас, но защитную проверку стоит
  усилить на `if (!bonusBalance || bonusBalance <= 0) return null` — на
  случай, если подобный разрыв контракта повторится в другом месте.

## Fuel (главный экран заправки: метод → АЗС/колонка → топливо → литры)

- **`GetLocationOfAzs.tsx`** (`src/features/Fuel/GetLocationOfAzs/ui/GetLocationOfAzs.tsx:126-134`) —
  когда геолокация включена и запрос к `get_azs_geo/` успешно отработал,
  показывается тост «Геолокация включена. Азс будет определяться
  автоматически.» — но по факту ничего не подставляется:
  `FuelSelectAzsAndColumnWidget.handleSelectGeoAzs` — намеренная заглушка
  `(_azs) => {}` (см. комментарий там же), потому что `get_azs_geo/` отдаёт
  легаси-числовой id, несовместимый с id станций Топаз (строка). Сам факт
  отключённого автоподбора — уже задокументированное, осознанное
  ограничение (`plans/topaz-fuelling-integration-design.md`), но конкретно
  этот текст тоста никто не поправил — он лжёт пользователю, что станция
  подставится сама, хотя её всё равно нужно выбирать вручную на следующем
  шаге. Заодно сам запрос к `get_azs_geo/` продолжает уходить и тратить
  время геолокации впустую, раз результат всё равно отбрасывается.
