# Передизайн экранов-статей под макет «21 Век»

Экраны: **«О компании»**, **«О приложении»**, попутно — **«Помощь»**.

## Зачем

`features/GetArticle` оставался последним местом в проекте на легаси-рендере статей. Текст с бэкенда рисовался голым `RenderHTML` мимо палитры: цвет задавался как `colorTheme == EColorThemes.DARK ? 'white' : undefined`, шрифт оставался системным вместо Manrope, а сам текст лежал прямо на фоне экрана — без стеклянной карточки, в которой статьи живут на всех переделанных экранах.

При этом нужный рецепт уже был обкатан в деталях новости и акции:

```tsx
<GlassCard variant="glass2" radius={RADII.CARD} padding={18}>
    <HtmlContent html={...} />
</GlassCard>
```

`shared/HtmlContent` (WebView с CSS на токенах проекта + синхронный `RenderHTML`-фоллбэк, пока WebView меряет высоту через `postMessage`) уже раскладывает `h1..h6`, `p`, `a`, `b/strong`, `hr`, таблицы и картинки по `COLORS`, `FONTS`, `SIZES.PX`, `RADII.ROW` и `line-height: 1.55` из макета.

**Поэтому это одна централизованная правка фичи, а не переверстка трёх экранов.** Все три экрана — тонкие обёртки над `GetArticle`, собственной вёрстки у них нет.

**Бэкенд не менялся:** тот же `article/` с `id`, те же поля `IGetArticleData`.

| Было | Стало |
|---|---|
| текст на голом фоне экрана | `GlassCard variant="glass2"`, `RADII.CARD`, padding 18 |
| `color: theme === DARK ? 'white' : undefined` | токены `TEXT.Primary` / `TEXT.Secondary` из `HtmlContent` |
| системный шрифт | Manrope 600/700/800 (`FONTS.*`) |
| ссылки цветом браузера, никуда не ведут | `ACCENT.Primary`, открываются наружу через `Linking` |
| `Loader` в блоке `SIZES.HEIGHT(0.7)` | `GetArticleSkeleton` — шиммер в такой же карточке |
| картинки/видео/iframe без стилей | `max-width:100%`, `RADII.ROW`, у iframe `aspect-ratio: 16/9` |

## Решения, принятые до кода

| Вопрос | Решение |
|---|---|
| В макете «О компании» — это ещё вордмарк и строка-переход «Контакты», «О приложении» — вордмарк, версия и группа из трёх строк | **Верстаем только текст в стекле.** Остальное — в расхождениях ниже |
| Дублировать ли `data.header` внутри карточки | **Нет.** Заголовок уже выводит шапка (`SCREENS_TITLES` → `InternalPagesHeader`) |
| Ошибка загрузки: `CenteredState` или `ErrorWhileFetchingForm` | **`ErrorWhileFetchingForm`** — правило 4 `architecture.md`; так же поступает переделанный `NewsWidget` |
| Менять ли типографику под эти экраны | **Нет.** `shared/HtmlContent` общий, его CSS используют ещё детали новости и акции |

## Расхождения с макетом

Осознанно не сверстано — в макете у этих элементов **нет обработчиков**, а в приложении нет данных, чтобы их подключить:

| Элемент | Экран | Чего не хватает |
|---|---|---|
| Вордмарк по центру | О компании, О приложении | ничего, но без остальных блоков он повисает в воздухе — вернуть вместе с ними |
| Строка-переход «Контакты» | О компании | ведёт в `ESCREENS.CONTACTS`, подключается тривиально — отложена вместе с блоком |
| Подпись «Версия» | О приложении | в макете литерал `2.0.0`, в `app.config.ts` сейчас `1.3.3`; нужно решить, брать из `expo-constants` или из `APP_VERSION` (там своё значение `1.0.0`, расходится с конфигом) |
| «Условия использования» | О приложении | нет URL документа |
| «Политика конфиденциальности» | О приложении | нет URL документа |
| «Оценить приложение» | О приложении | нет store-ссылок (App Store / Google Play ID) |

Отдельно: в макете статья — это один абзац на 197 символов. Как карточка ведёт себя на трёх экранах текста, дизайнером не проверено; вертикальный ритм длинной статьи (отбивки между абзацами, заголовки внутри) задаётся CSS из `shared/HtmlContent`, а не макетом.

## Проверка

- `npx tsc --noEmit` — 16 ошибок до правки и 16 после, вывод идентичен baseline. Новых ошибок не добавлено (все 16 — предсуществующие, в `WheelPicker` и прочем legacy).
- `npx prettier --check` по всем изменённым файлам — проходит.
- Тестов и линтера в проекте нет.

**Не проверено на устройстве** — требуется dev-билд (в Expo Go проект не запускается). Проверить руками:

1. Профиль → «О компании», «О приложении», «Помощь»: скелетон при загрузке → текст в стеклянной карточке.
2. Заголовки, абзацы и ссылки шрифтом Manrope; ссылки лаймовые и открываются наружу.
3. Карточка не обрезает длинный текст (высота WebView приезжает через `postMessage`).
4. **Обе темы** — переключатель в Профиле.
5. **Android отдельно**: там `CAN_BLUR = false`, стекло падает на непрозрачный `GLASS.SolidSecondary`.
6. Оборвать сеть → `ErrorWhileFetchingForm` с рабочей кнопкой «Попробовать снова».
