# Передизайн сценария кофе под макет «21 Век»

## Зачем

Кофе был последним крупным сценарием на старой дизайн-системе. Вокруг него всё уже переделано (главная, баланс, топливо, бонусы, профиль, новости), а сам кофе жил на `BACKGROUND.Tertiary`, `displaySmall`, `CustomButton` и хардкоде `#F8F8F8`. Выбор кофемашины был собран на `FuelMainBlock` — компоненте старого дизайна, который после передизайна топлива больше нигде, кроме кофе, не использовался.

**Бэкенд не менялся:** те же пять эндпоинтов, те же поля.

| Шаг | Было | Стало (макет) |
|---|---|---|
| **Вкладка** | таб-бар «КУПИТЬ КОФЕ» / «Мои кофе» | сегмент «Мой кофе» / «Купить» (dc.html:203–206) |
| **Выбор кофемашины** | два `FuelMainBlock` r16 + 4 локальных SVG с ветвлением по теме | две карточки-действия r24 с иконками из `ICONS` (dc.html:237–238) |
| **Список кофемашин** | сетка фото-карточек r15 | стеклянные строки r20 с миниатюрой и названием АЗС (dc.html:499–502) |
| **Меню напитков** | сетка карточек на `#F8F8F8`, `displaySmall` | сетка стеклянных плиток r22, `rowTitle` + `num16` |
| **Подтверждение** | боттом-шит с двумя кнопками сверху | отдельный шаг: круг 96, CTA-пилюля, «Отмена» (dc.html:615–623) |
| **Успех** | сразу переброс на вкладку | `CenteredState` с лаймовым кругом и CTA «Налить кофе» (dc.html:645–652) |
| **Мой кофе** | QR на `BACKGROUND.Tertiary` + строки с заливкой `BRAND.Primary` | `QrBlock` r28 + группа `ListRow` с подсветкой выбранной |
| **Сканер** | голый кадр камеры с хаком по ширине | вьюпорт r28 с лаймовой рамкой и бегущим лазером |

## Решения, принятые до кода

| Вопрос | Решение |
|---|---|
| Макет рисует меню строками с общей иконкой кофе, объёмом и ценой, но API отдаёт `img` и `discount`, а объёма не отдаёт | **Оставлена сетка с фото**, перекрашенная в стекло. Фото и скидки — то, что реально есть в данных и чего в прототипе просто не нарисовали |
| Подтверждение: боттом-шит или отдельный экран | **Отдельный шаг** со `StepHeader` — единообразно со сценарием налива |
| Бонусный кофе: отдельный роут или влить в общее меню | **Роут `/coffee_bonus` оставлен**: за ним свой запрос `bonus: 1` с другим списком напитков, влить без правок бэка нельзя |
| Оверлей сканера | **Сделан** в `shared/CameraScanner` — достался заодно и сканеру топлива |
| В макете шаги — push-экраны, в коде — один роут | Как в топливе: шаги остались состояниями `TCoffeeRoad` внутри роута, сверху `entities/StepHeader`. Новых `ESCREENS` не заведено |

### 2. Машина состояний

Оба процесса крутят одну машину; `road` и выбранный напиток живут локальным состоянием, как в топливе.

```
/coffee, вкладка «Купить»                    /coffee_bonus (без вкладок)
main    лаймовая карточка бонуса +           main    две карточки-действия
        две карточки-действия + подсказки            + подсказка
scan    StepHeader → камера с оверлеем       scan    то же
select  StepHeader → список кофемашин        select  то же
menu    StepHeader → сетка напитков          menu    сетка бесплатных напитков
confirm StepHeader → круг + CTA + «Отмена»   confirm то же, type="bonus"
success CenteredState → «Налить кофе»        success → router на /coffee?road=muy
        → вкладка «Мой кофе»
```

Кофемашина единственная → `main` пропускается, открывается сразу `menu` (прежнее поведение сохранено).

### 6. Знак валюты: «B» → «₽» (за пределами кофе)

[BonusIcon.tsx](../src/shared/BonusIcon/ui/BonusIcon.tsx) рисовал знак валюты иконкой `name="bold"` из `@expo/vector-icons` — на экране это выглядело как латинская «B». Заменён на символ **₽** шрифтом Manrope через `Typography`: так глифа совпадает по начертанию с числом, к которому приписана, и соответствует макету (в прототипе валюта везде обычным текстом — `{{ c.price }} ₽`, «Списано: 120 ₽»).

Контракт пропсов (`size`, `bold`, `color`, `ml`, `mt`) сохранён, поэтому все **8 мест вызова** правок не потребовали: кофе, `BalanceCard`, `HistoryItem`, детали истории, перевод баланса, `CustomPieChart`.

Заодно:
- цвет по умолчанию берётся из `ThemeStore.useCOLORS()` вместо статического `COLORS` с ручной веткой по теме — это и правило проекта, и одна ветка вместо трёх;
- компонент обёрнут в `memo` (не был);
- удалён осиротевший `shared/BonusIcon/assets/bonus.svg` — он импортировался, но не рендерился ещё до правки (одноимённый файл в `shared/Icons/assets/` не тронут, он живой).

⚠️ **Что проверить глазами:** иконка центрировалась в квадратном боксе, а текст сидит на базовой линии — подобранные под иконку сдвиги `mt` на некоторых экранах могут потребовать подгонки на 1–2 px. Смотреть: карточка баланса, строка истории, `CustomPieChart`, подтверждение покупки кофе.

Имя `BonusIcon` осталось прежним, хотя компонент теперь рисует не бонусы, а валюту: переименование задело бы 8 файлов и в задачу не входило.

## Расхождения макета и API

Верстали под то, что реально отдаёт бэкенд:

| В макете | Реальность | Как поступили |
|---|---|---|
| Объём напитка «300 мл» под названием | В `ICoffeeItem` поля нет | Подпись не рисуем, объём остаётся в названии позиции |
| «до 30.07» в строке «мой кофе» | Даты сгорания в ответе нет | Дату справа не рисуем |
| «АЗС №12 — кофемашина у кассы» в строке «мой кофе» | Бэкенд добавил `coffee_machine_name` | Выводится подписью под названием; при `null` подписи просто нет |
| Расстояние «0.4 км» у кофемашины | Геолокации в этом сценарии нет | Вместо расстояния — `azs_name` |
| «Каждый 6-й бесплатно», прогресс накопления | Бэк отдаёт только `bonus` — счётчик готовых бесплатных | Показываем счётчик, прогресс не выдумываем |
| Кнопка «Кофемашина №3 найдена» на сканере | Имитация распознавания в прототипе | Переход инициирует `onScan` камеры |
| Ветка «нет моего кофе» | `hasMyCoffee` в макете захардкожен `true` | Дорисована — без неё экран пустой |
| Цены в ₽ | В приложении своя валютная глифа `BonusIcon` | Оставлен `BonusIcon`, как на всех остальных экранах |

## Проверка

- `npx tsc --noEmit` — **16 ошибок до правок, 16 после, набор идентичен** (проверено `diff`). Все они предсуществующие и лежат в `RangePicker`, `CustomSelect`, `CustomInput`, `WheelPicker`, `TabBar*`, `CustomButton`, `app/_layout` и одном экране акций. В CLAUDE.md записано «~39» — цифра устарела.
- `npx prettier --check` по всем изменённым файлам — чисто. Единственное исключение, `src/shared/index.ts`, не проходило проверку и **до** правок: это сгенерированный бочонок с точками с запятой и двойными кавычками, зафиксированный в код-стайле как долг. Добавленная строка написана в стиле самого файла.
- Матрица импортов FSD проверена: боковых импортов (`entities→entities`, `features→features`, `widgets→widgets`) и импортов «вверх» в новом коде нет.
- Хардкода цветов, голых `<Text>` и новых `any` / `@ts-ignore` в кофейном контуре нет.

**Автотестов и линтера в проекте нет** — заявлять, что «тесты прошли», нельзя.

### Что осталось проверить руками на устройстве

Нужен dev-билд (камера, в Expo Go не запустится):

1. Сценарий целиком: «Купить» → «Выбрать из списка» → кофемашина → меню → напиток → подтверждение → успех → «Мой кофе», QR виден.
2. Ветка сканера: оверлей (уголки + бегущий лазер), распознавание `coffee_machine_id=<id>`. **Отдельно убедиться, что не сломался сканер топлива** — `FuelScanBarcodeWidget` использует тот же `CameraScanner`, а его вёрстка изменилась.
3. Ветка бонуса: лаймовая карточка → `/coffee_bonus` → выбор → подтверждение → возврат на «Мой кофе».
4. Состояния: пустой список «мой кофе», ошибка загрузки, скелетоны меню / списка кофемашин / строк.
5. **Обе темы** — переключатель в Профиле (`features/ChangeColorTheme`).
6. Android: у лазера не будет свечения (`shadow*` там не работает), стекло отрисуется непрозрачными `GLASS.Solid*` — это ожидаемо.

Пересборка dev-билда **не требуется**: новых нативных модулей не добавлено, reanimated и expo-camera уже стояли.
