# Передизайн экрана «Цены на топливо» под макет «21 Век»

## Зачем

Экран `/fuel_prices` оставался на старом дизайне, пока главная, авторизация и пополнение баланса уже переехали на «21 Век». Внутри новой обвязки (`InternalPagesLayout` с амбиентным фоном и стеклянной шапкой) лежала сетка 2×N из плиток на старых токенах: `COLORS.BACKGROUND.Tertiary`, хардкод `borderRadius: 10 * SIZES.PX` мимо `RADII`, старая шрифтовая лестница (`bodySmall`, `caption`, `bodyAccentSmall`). Экран выглядел вставкой из прошлой версии приложения.

Макет ([`design/21vek-app.dc.html`](../design/21vek-app.dc.html), `showPrices`, строки 361–370) рисует вместо сетки вертикальный список стеклянных строк: цветной бейдж с кодом марки слева, полное название, крупная цена справа.

**Бэкенд не менялся:** `GET get_fuel_prices/ {token}` → `{ prices, info }` работает как прежде.

## Что сделано

### 1. Токены — централизованно, до вёрстки

| Файл | Изменение |
|---|---|
| [TYPOGRAPHY_SCALE.ts](../src/shared/Typography/config/constants/TYPOGRAPHY_SCALE.ts) | + `num17` (800/17) — цена в строке (dc.html:366); + `num12` (800/12) — код марки в бейдже (dc.html:365). Обоих весов в лестнице не было: ближайший `caption12` — это 600, бейдж бы поплыл |
| [COLORS.ts](../src/shared/common/config/constants/COLORS.ts) | + `ACCENT.Diesel: '#9BD3FF'` (dc.html:924) в **обе** палитры одинаковым значением — как `ACCENT.OnLime` и `PrimarySoft`: это тонировка бейджа, от темы не зависит |

`SPACING` не трогали. Макету нужны `gap: 10` и `paddingHorizontal: 18`, которых в шкале нет — пишем сырыми `* SIZES.PX`, ровно как уже сделано в `ListRow` (`paddingVertical: 15`, `paddingHorizontal: 18`). Расширять шкалу ради двух значений одного экрана незачем.

### 2. Новая entity `entities/Fuel/FuelPriceRow`

Строка списка — чистое отображение пропсов без запросов и стора → слой `entities/` (правило 1 [architecture.md](../.claude/rules/architecture.md)).

```
entities/Fuel/FuelPriceRow/
    index.ts
    ui/FuelPriceRow.tsx
    ui/FuelBadge.tsx                    вспомогательный, наружу не торчит
    config/interfaces/IFuelPriceRow.ts
    config/types/TFuelModifier.ts
    lib/getFuelBadge.ts
    lib/formatPrice.ts
```

**`ListRow` из UI-кита не переиспользован.** У него зашиты `paddingVertical: 15` (нужно 16), заголовок `label14` (нужен `rowTitle`), `value` рендерится как `label14` (нужен `num17`), а `left` рисуется как `<Icon size={24}>` — здесь же прямоугольный бейдж 48×42. Расширять `ListRow` четырьмя пропами рискованнее, чем завести entity: у него уже есть потребители в профиле и настройках.

```ts
export interface IFuelPriceRow {
    name: string
    price: number
    discount?: TFuelModifier
    bonus?: TFuelModifier
    unit?: string        // '₽' по умолчанию, '₽/л' — для экрана выбора топлива
    onPress?: () => void // задан → строка кликабельна
}
```

`onPress` и `unit` заложены сразу, чтобы `features/Fuel/SelectTrkTypeForm` переехал на эту же entity без её правки — в макете (dc.html:511–522) там байт-в-байт та же строка, отличается только кликабельностью и суффиксом «₽/л».

**Вёрстка:** `GlassCard variant="glass2" radius={RADII.ROW} paddingVertical={SPACING.XL} paddingHorizontal={18}`; ряд `space-between` с `gap: SPACING.MD`. Бейдж — `48 × 42 * SIZES.PX`, `RADII.BADGE`, фон `ACCENT.Lime` / `ACCENT.Diesel`, текст `num12` цветом `ACCENT.OnLime`. Название — `rowTitle` с `numberOfLines={2}`.

`PressableScale` руками не навешивался: `GlassCard` при наличии `onPress` оборачивает содержимое сам, а `PRESS_SCALE.CARD` и `PRESS_SCALE.ROW` в макете совпадают (0.97).

#### Скидка и кэшбек — чего в макете нет

Макет нарисован на фейковых данных и показывает только код, название и цену. API при этом отдаёт `discount` и `bonus` — по правилу 4 [design.md](../.claude/rules/design.md) верстаем под реальные данные, а не под прототип. Оба поля дорисованы языком макета:

```
┌────────────────────────────────────────────┐
│ ┌────┐  Бензин АИ-92            52,40 ₽    │  ← caption11, secondary, зачёркнуто
│ │АИ92│  Кэшбек 2 ₽              49,80 ₽    │  ← num17, ACCENT.Primary
│ └────┘                                     │
└────────────────────────────────────────────┘
```

Кэшбек — мелкая строка под названием цветом `STATE.Positive`. Скидка — вторая цена в правой колонке: старая зачёркнута `caption11 color="secondary"`, новая набрана `num17` цветом `ACCENT.Primary`. Так на самом заметном месте стоит сумма, которую человек реально заплатит, а геометрия строки из макета (текст слева, число справа) сохраняется.

Старый код красил скидку в `color="error"` — не переносили: выгода красным читается как ошибка. Формула расчёта перенесена дословно (`percent` → `price - price * value / 100`, иначе `price - value`).

#### `lib/getFuelBadge.ts` — код марки выводится на клиенте

Поля `code` в API нет, есть только полное `name` («Бензин АИ-92»), а бейдж требует короткий код. Бэкенд решили не трогать:

| Вход | Выход |
|---|---|
| `Бензин АИ-92`, `Аи92`, `AI-100` | `АИ-92` / `АИ-92` / `АИ-100`, лайм |
| `Дизельное топливо`, `ДТ`, `ДТ-Евро`, `Евро ДТ` | `ДТ`, голубой |
| `Премиум`, `Газ пропан` | первое слово ≤6 символов, лайм |

Границу аббревиатуры **нельзя** писать через `\b`: в JS `\b` строится на `[A-Za-z0-9_]`, для кириллицы не работает. Поэтому требуем, чтобы рядом с «дт» не стояло букв — `(^|[^А-Яа-яЁёA-Za-z])дт([^А-Яа-яЁёA-Za-z]|$)`. С первой версией регулярки (`(^|\s)дт($|\s)`) «ДТ-Евро» оставался лаймовым, потому что после аббревиатуры стоял дефис. Проверено на 15 вариантах названий: «Нанодт» ложно не срабатывает.

Фолбэк никогда не пустой и никогда не длиннее бейджа — новая марка топлива не сломает строку, а отрисуется лаймовым бейджем с обрезанным словом.

#### `lib/formatPrice.ts`

`price.toFixed(2).replace('.', ',')` — макет пишет цену через запятую (`'52,40'`), старый код через точку. `divideNumber` из `shared` не подошёл: он разбивает разряды, а цена за литр всегда двузначная.

### 3. Виджет `widgets/FuelPricesWidget`

Слайс остался по текущему пути (не переехал в `widgets/Fuel/`) — переезд ломал бы импорт в экране без выигрыша.

- Виджет **обёрнут в `memo`** — `memo` был импортирован, но не применён.
- Список — прямой `map` по `FuelPriceRow` в `View` с `gap: 10 * SIZES.PX`. Промежуточная фича `MapFuelPricesPriceBlocks` не нужна: это композиция без пользовательского действия. Тот же ход уже сделан в `PayBalanceWidget`, где `MapInfoBlocks` заменили прямым `map` по `InfoCard`.
- Инфо-блок — `<InfoCard {...data.info} />` в `MPLayout mt={SPACING.SECTION}` вместо `ShowFuelPricesInfo` + старого `InfoBlock`. `entities/InfoCard` создан в прошлом заходе ровно под это, `IInfoCard` совпадает по форме с `IInfoBlock`.
- Загрузка — новый `FuelPricesWidgetSkeleton` вместо `<Loader mt={100} />`.
- Пусто (`prices` пустой) — `CenteredState variant="empty"` с кнопкой «Обновить». В макете ветки нет, но список приходит с бэка.
- Ошибка — `ErrorWhileFetchingForm` остался (правило 4 architecture.md).
- Ответ типизирован дженериком: `useFetchData<IFuelPricesWidgetData>` — раньше вызывался без него.

#### Починен мигающий лоадер при возврате на экран

`useFocusEffect` перезапрашивает цены на каждом фокусе, а `isDataLoading` стартует в `true` — то есть каждый повторный вход на экран стирал уже показанные данные полноэкранным лоадером. Условие изменено на `isDataLoading && !data`: скелетон показывается, только пока показывать нечего.

#### Новый `FuelPricesWidgetSkeleton`

Четыре плашки шириной `SIZES.WIDTH(1) - 40 * SIZES.PX` (экран минус `paddingHorizontal: 20` у `InternalPagesLayout`) высотой 74 (бейдж 42 + паддинги 16×2), `gap: 10`, ниже — плашка инфо-карточки. У `Skeleton` радиус зашит `RADII.INPUT`, перекрыт через `style` на `RADII.ROW` / `RADII.CARD`.

#### Интерфейсы

Тип элемента прайса переехал из удаляемой entity в виджет — это форма ответа API, а не пропсы компонента:

```ts
// config/interfaces/IFuelPriceItem.ts
export interface IFuelPriceItem {
    id: number
    name: string
    price: number
    discount?: TFuelModifier
    bonus?: TFuelModifier
}

// IFuelPricesWidgetData.ts
export interface IFuelPricesWidgetData {
    prices: IFuelPriceItem[]
    info: IInfoCard
}
```

## Осознанные отклонения от макета

| Что | Почему |
|---|---|
| **Валюта ₽** | Макет нарисован под российский рынок, приложение азербайджанское. Оставили ₽ — как в старом коде и на уже переделанной главной. Символ вынесен в проп `unit` у entity, смена валюты станет правкой одного дефолта |
| **Скидка и кэшбек** | В макете отсутствуют, дорисованы языком макета (см. раздел 2). Решение согласовано |
| **`code` / `kind` марки** | Не поля API, считаются на клиенте. Кандидаты в опциональные поля `prices[]`, если парсер начнёт ошибаться на новых марках — тогда правится один `getFuelBadge.ts` |
| **Цены не привязаны к станции** | На экране «Выберите топливо» макет пишет «Цены актуальны для этой станции», но на самом экране цен выбора станции нет и открывается он с главной вне контекста АЗС. Противоречие внутри макета — решать продуктово |
| **Нет pull-to-refresh и даты обновления цен** | В макете их нет; данные и так перезапрашиваются на каждом фокусе экрана |

## Замеченное, но не тронутое

- **`DESIGN_SPEC.md` разошёлся с макетом**: номера строк для экранов начиная с `showFuel` уехали на +6 относительно текущего `dc.html`, и амбиентные блобы описаны неверно — в макете их три, а не два, с другими альфами.
- **`features/Fuel/SelectTrkTypeForm`** (шаг выбора топлива в наливе) в макете использует ровно ту же строку. В объём не входил; `FuelPriceRow` заранее принимает `onPress` и `unit`, так что переезд — это замена вёрстки в одном файле.
- **Блок-подсказка** «заголовок 700/14 + подпись 600/12» повторяется в макете на шести экранах — кандидат в `shared/`, здесь не понадобился.

## Проверка

**Тестов, линтера и lint-скрипта в проекте нет — они не запускались, потому что их не существует.**

- `npx tsc --noEmit` — **29 ошибок и до, и после**; `diff` отсортированных выводов пуст, набор ошибок совпадает с базовой линией посимвольно. Новых ошибок ноль.
- `npx prettier --check` на всех созданных и изменённых файлах — проходит.
- Мёртвых ссылок на удалённые слайсы в `src/` не осталось (греп пуст).
- `getFuelBadge` прогнан отдельным скриптом на 15 названиях — таблица в разделе 2.

### Что НЕ проверено — нужен прогон на устройстве

Изменения проверены только компилятором. В Expo Go проект не запускается, нужен dev-билд (`yarn ios` / `yarn android`).

1. **Обе темы** через переключатель в Профиле — правило 5 [design.md](../.claude/rules/design.md).
2. **Android**: `CAN_BLUR === false`, все стёкла отдают `GLASS.SolidSecondary` — не сливается ли список из четырёх строк подряд с фоном.
3. Строка **с `discount`**, **с `bonus`**, **с обоими**, **без ничего** — проверяется подменой ответа `get_fuel_prices/` руками.
4. Бейджи на реальном прайсе: бензины лаймовые, дизель голубой, длинное название не выталкивает цену за край.
5. Скелетон при первом входе; **повторный вход** на экран — цены остаются на месте, лоадера нет.
6. Пустой `prices` → `CenteredState`; обрыв сети → `ErrorWhileFetchingForm` и кнопка «Попробовать снова».
