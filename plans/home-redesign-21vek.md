# Передизайн главной страницы под макет «21 Век»

## Зачем

Фундамент дизайн-системы «21 Век» (токены, лестница `Typography`, примитивы) и оболочка главной — шапка, амбиентный фон, плавающий таб-бар — были сделаны раньше (см. [design-system-21vek-foundation.md](design-system-21vek-foundation.md)). Контент главной при этом остался на старом дизайне: экран выглядел разорванным — новая шапка и таб-бар вокруг старых плиток с хардкод-цветами.

Заход приводит **весь экран** к макету: карточка баланса, герой, сетка 2×2, акции двух видов, новости горизонтальной каруселью, модалка акций.

## Что сделано

### Новые файлы в существующих слайсах

`NewsCard` + `NewsCardSkeleton` (в `entities/News/NewsItem`), `HomePromotionCard` + `PromotionImageCard` (в `entities/PromotionsAndBonuses/PromotionsAndBonusesItem`), `HomeMainWidgetSkeleton` и `THomeTexts` (в `widgets/Home/HomeMainWidget`).

Отдельными слайсами их делать было нельзя: это второе представление того же доменного объекта, а интерфейсы (`INewsItem`, `IPromotionsAndBonusesItem`) лежат в этих слайсах — новый слайс потребовал бы бокового импорта. Побочный плюс: `PromotionsAndBonusesItem.tsx` **не редактировался вообще**, поэтому экраны `/bonuses`, `/bonuses/details` и `ImageCarousel` не задеты.

### Акции — два вида

Заказчик подтвердил: акции бывают картинкой и текстовой строкой, вид приходит с бэка.

`HomePromotionCard` выбирает ветку внутри entity, а не в фиче — поэтому `ShowMainPromotions` остался однострочным `map`, и появление `view_type` не потребует правок слоя `features`:

```
view_type 'text' → PromoRow (лаймовая строка)
иначе            → PromotionImageCard (фото + скрим + текст)
```

Фолбэк — `view_type ?? (img ? 'image' : 'text')`: без картинки image-вид выглядел бы сломанным.

Навигация уехала из entity в фичу через `onPress`.

### Переверстанные фичи

- 4 плитки — на `HomeQuickTile` + `<Icon name="home_*">`. Ушли 8 пар `*.svg`/`*_dark.svg` и тернарники по теме.
- Герой «Заправить авто» — `GlassCard variant="hero"` с лаймовым кругом-стрелкой. Ушёл `BackgroundImage`.
- «Пополнить»/«Перевести» — два `PillButton` вместо двух байт-в-байт одинаковых наборов стилей.
- Кофе-бонус — на `PromoRow`.
- `ShowPromotionsModal` — целиком на `CustomModal`.

### Новости

`NewsWidget` получил `variant?: 'list' | 'carousel'` с дефолтом `'list'` — экран `/news` (второй потребитель виджета) не изменился ни на пиксель. Один фетч, один store, две раскладки.

На главной секция целиком скрывается, если новостей нет: `WithoutNewsBlock` с его lottie остался вертикальному списку.

## Ширина плитки сетки

```
контент = W − 2×20*PX (paddingHorizontal у (main)/_layout) = W − 40*PX
2×tile + 12*PX gap = W − 40*PX  →  tile = W/2 − 26*PX
```

В макете было бы −22: там паддинг контейнера 16, а у нас 20. Проверка на 390 pt: `195 − 26.4 = 168.6` = `(349.4 − 12.2)/2`.

### `bonus_balance` — во всех ответах, где приходит `balance`

Макет развели на два числа: рублёвый баланс (`{{ balText }} ₽`) и бонусы (`{{ bonusText }} B`). `UserStore` теперь хранит оба, `setBalance` принимает `{ balance, bonus_balance }` — значит **каждый** ответ, из которого баланс кладётся в стор, обязан отдавать оба поля:

| Запрос | Куда идёт |
|---|---|
| `GET /home/` | главная, карточка баланса |
| `GET get_balance/` | `useGetBalance` — экран баланса, топливо, налив |
| `GET profile/` | профиль |
| `GET get_client/` (перевод) | подтверждение перевода |
| ответ выбора типа ТРК | `SelectTrkTypeForm` |
| ответ сканирования штрихкода | `FuelScanBarcodeWidget` |
| ответ покупки кофе | `BuyCoffeeWidget` |

Если в каком-то из них поля не будет, в сторе окажется `undefined` и бонусы отрисуются как `0` — приложение не упадёт, но число будет неверным.

Чип в шапке по новому макету показывает **рубли со знаком ₽**, иконка бонуса из него убрана — бонусы остались только в карточке на главной.

### Скрытие баланса

Макет добавил круглую кнопку 26 у надстрочника «БАЛАНС» — глаз / перечёркнутый глаз. Скрытое состояние подменяет суммы на `•• ••• ₽` и `••• B` **одновременно в карточке и в чипе шапки**, поэтому флаг лежит в `UserStore.isBalanceHidden`, а не в локальном состоянии карточки.

Флаг **персистится** в AsyncStorage (`EAsyncStoreKeys.IS_BALANCE_HIDDEN`) и восстанавливается в `getUser()` — до первой отрисовки шапки. В макете персистентности нет вовсе (это прототип), но без неё баланс открывался бы заново при каждом запуске, и смысл функции терялся бы.

Кнопка — `features/Home/ToggleBalanceVisibility`, приходит в `BalanceCard` пропом `visibilityAction`. Плейсхолдеры — в `HIDDEN_BALANCE` (`shared`), чтобы карточка и шапка не разъезжались.

Бэкенд не затронут.

### Перевод бонусов на счёт — нужен новый эндпоинт

Макет добавил круглую кнопку у числа бонусов и модалку перевода бонусов на основной счёт по курсу **1 B = 1 ₽**. Сделано в `features/Home/ConvertBonusToBalance`; кнопка приходит в `BalanceCard` пропом `bonusAction`, чтобы entity не импортировала feature.

Эндпоинт **выбран по аналогии с соседними и на бэке пока не подтверждён**:

```
GET balance/convert_bonus/?token=<token>&sum=<сколько бонусов перевести>
→ { balance: number, bonus_balance: number }   // оба уже пересчитаны
```

Если фактический путь или имя параметра другие — правится один файл `api/convertBonusToBalanceApi.ts`. Ответ должен вернуть оба баланса, иначе после перевода на экране останутся старые числа до следующего запроса `/home/`.

Поведение: кнопка не рендерится при `bonus_balance <= 0`; поле открывается заполненным всей суммой; ввод зажимается в `[0, bonus_balance]`; пресеты «Половина» и «Все N B».

**Отступления от макета в токенах:** (а) `PillButton size="md"` даёт primary-подпись `num15` (800/15), макет просит 700/14 — такого типа для primary в лестнице нет; (б) «бонусов» в макете 700/18, в лестнице только `num18` (800/18).

## Проверка

**Тестов, линтера и lint-скрипта в проекте нет — они не запускались, потому что их не существует.**

- `npx tsc --noEmit` — **29 ошибок против базовых 32**. Новых файлов с ошибками ноль; починились `HomeMainBlock` (удалён), `HomeMainWidget`, `INewsWidgetApiData`.
- Prettier — весь новый код проходит `--check`. Незакрытыми остались `GlassCard`, `Typography`, `ImageCarousel`, `IPromotionsAndBonusesItem` и два `index.ts`: проверено через `git show HEAD`, все были неформатированы **до** правок, переформатирование раздуло бы диф чужими изменениями.

### Что ещё НЕ проверено — нужен прогон на устройстве

Ничего из перечисленного не запускалось: изменения проверены только компилятором.

1. **Обе темы** через переключатель в Профиле — [design.md](../.claude/rules/design.md) Правило 5.
2. **Android**: `CAN_BLUR = Platform.OS === 'ios'`, значит все стёкла отдают `GLASS.Solid*`. Шесть стёкол подряд — главный риск читаемости; если сетка «сливается», поднять плиткам уровень до `glass2`.
3. **Вложенный горизонтальный скролл** карусели новостей внутри `KeyboardAwareScrollView` — не залипает ли вертикальный скролл при старте жеста на карусели.
4. **Аккаунт с урезанным `options`** — сетка на 1, 2, 3 плитках; карточка баланса без кнопок.
5. **Акции обоих видов** — подменить `view_type` руками в ответе.
6. **Затронутые сторонние экраны**: `/coffee` (кофе-бонус), `/news`, `/bonuses`, `/bonuses/details`, `/balance`.
7. FPS при скролле: `AmbientBackground` крутит два бесконечных `withRepeat`, плюс `PressableScale` на каждой плитке.

`expo-blur` требует свежего dev-билда — без него iOS-стёкла не проверить.
