# Код-стайл и именование

## Правило 1. Форматирование — по [.prettierrc.cjs](../../.prettierrc.cjs)

4 пробела, **без точек с запятой**, одинарные кавычки, `trailingComma: es5`.

Часть старых файлов (в т.ч. сгенерированный `src/shared/index.ts`) написана с точками с запятой и двойными кавычками — это долг, равняться на него не нужно. Новый код пишем по конфигу.

## Правило 2. Именование

| Что | Как | Пример |
|-----|-----|--------|
| Интерфейс | `I` + PascalCase | `IUserStore`, `IGetAzsListData` |
| Енам | `E` + PascalCase, значения UPPER_SNAKE | `EScreens`, `EAuthMethod` |
| Тип-алиас | `T` + PascalCase | `TSuccessScreenParams`, `TTypographyTypes` |
| Стор | `xxxStore.ts` в `model/` | `userStore.ts`, `HomeStore.ts` |
| API | `xxxApi.ts` в `api/` | `selectAzsAndColumnApi.ts` |
| Компонент | PascalCase, файл = имя компонента | `ui/SelectAzsAndColumn.tsx` |

Имя папки слайса совпадает с именем его основного компонента.

⚠️ В коде уже есть закрепившиеся опечатки в публичных именах — `axiosIntsanse`, `proccesses/`, `getUserIsLoadung`. Их **не** переименовываем походя (сломает импорты), пишем как есть.

## Правило 3. Компоненты

- Функциональные компоненты, обёрнутые в `memo`.
- Пропсы — локальный `type Props = { ... }` в том же файле (или `interface Props extends ViewProps`).
- Обработчики — `handleXxx`, обёрнутые в `useCallback` с честными зависимостями.
- Один экспортируемый компонент на файл; вспомогательные подкомпоненты — в соседние файлы `ui/`.

## Правило 4. Язык

Тексты интерфейса, тексты ошибок для `errorText`, комментарии и отчёты в `plans/` — **на русском**. Имена переменных, функций и файлов — на английском.

## Правило 5. Типизация

`strict: true`. Новые `any`, `@ts-ignore` и `as unknown as` не добавляем — в проекте они уже есть, но это долг. Ответы API описываем интерфейсом в `config/interfaces/`, а не выводим из `any`.

## Правило 6. Что не трогаем без запроса

- Версии зависимостей и `yarn.lock` — Expo SDK держит их согласованными.
- `version` / `android.versionCode` в [app.config.ts](../../app.config.ts) — меняются только при релизе, и всегда вдвоём.
- Существующие ~39 ошибок `tsc --noEmit` — фоновая проблема, а не задача текущего изменения; важно лишь не добавлять новых.
