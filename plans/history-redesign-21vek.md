# Передизайн истории операций под макет «21 Век»

## Зачем

История оставалась последней крупной непеределанной областью приложения. Home, Fuel, Coffee, Profile, News, Balance, Bonuses и Auth уже жили на новых примитивах, а обе ветки истории (`/history` и `/history_details`) — на старой вёрстке: `BACKGROUND.Tertiary`, скругления через `isFirst/isLast`, старые типы `Typography`, растровая заглушка `blured.png`, `AntDesign`-иконки, хардкод цветов мимо палитры. Переход «главная → история» визуально ломал приложение пополам.

Попутно закрыты три вещи, лежавшие в тех же строках:

- **последнее нарушение слоёв FSD** — `HistoryWidget` был единственным виджетом во всём слое, импортировавшим `layouts/`;
- **два живых бага** — на старте экрана уходило 4 запроса вместо 2, при долистывании первая страница дублировалась в списке;
- **`react-native-gifted-charts`** остался без потребителей.

## Решения, принятые до кода

| Развилка | Решение |
|---|---|
| Пончик: в макете 3 сектора, у API до 5 типов | 5 честных сегментов по типам операций + компактная легенда под кольцом. Геометрия и центр — по макету |
| Экран деталей | Переделан вместе со списком: макет схлопывает три разных тела в одну группу ключ/значение |
| Баги запросов | Починены в этой же работе |
| Выбор периода | Два стеклянных поля «от»/«до» по макету, оба открывают существующую `RangePickerModal` — новую библиотеку под нативный date-picker не тянем |

## Что сделано

### 1. Токены сегментов

`shared/common/config/constants/COLORS.ts` — новая группа `HISTORY` (`Fuel / Coffee / PayBalance / Transfer / Cash`) в **обеих** палитрах. `Fuel` и `Coffee` — цвета первых двух секторов макета (`ACCENT.Primary`, `ACCENT.Lime`), остальные подобраны к палитре. Сняты хардкоды `'#fc7f03'` и `'#3269ce'` и заимствование `ERROR.Secondary` / `BRAND.Primary` под цвета графика.

`SCREENS_TITLES` — заголовок `HISTORY_DETAILS` теперь «Детали операции» (был «История»), как в макете.

### 2. Новый примитив `shared/DonutChart`

Мультисегментное кольцо на `react-native-svg`: дуги через `strokeDasharray` + накопительный `strokeDashoffset`, поворот `-90deg`, пустой трек когда сумма нулевая. Радиус считается от фактического бокса, а не литералом из макета (`SIZES.PX` иначе разъедет дугу) — та же причина, что описана в `ProgressRing`.

**Отверстие честное**, а не круг цвета фона: сквозь него просвечивают блобы `AmbientBackground`. Из-за этого не понадобился и `transition: background .4s`, который в макете нужен был только затем, чтобы залитая дырка перекрашивалась при смене темы.

`ProgressRing` не тронут — он рисует одну дугу и используется на других экранах.

### 3. Период — два стеклянных поля

`shared/RangePicker/ui/RangePicker.tsx` переписан под `dc.html:289–297`: ряд из двух полей `flex: 1`, высота 44, `RADII.BADGE`, `Glass` + рамка, текст `body13` по центру, формат `dd.mm.yyyy`. Ушли `AntDesign`, хардкод `'#636F74'` и проп `styled` с ручным пересчётом ширины/высоты.

Форматирование даты вынесено в `lib/formatRangeDate.ts`. Вместе с ним из проекта ушли **два блока по 12 `case`** с названиями месяцев (в обоих `'06'` отдавал «Июль», а `'07'` — «Июнь»).

`RangePickerModal` перекрашен: статический импорт `COLORS` → `ThemeStore.useCOLORS()`, `rgba(0,0,0,0.49)` → `COLORS.EFFECTS.Backdrop`, поверхность → `GLASS.Surface` со скруглением `RADII.SHEET`, `CustomButton` → `PillButton`. Логика календаря не тронута.

### 4. Список операций

- `entities/History/HistoryItem` — строка по `dc.html:304–307`: слева заголовок цветом знака суммы и дата `caption11`, справа чип (`GLASS.Secondary`, `RADII.CHIP_SM`, `6/10`) с иконкой типа 18 и суммой `label13`. Своих скруглений у строки больше нет — их даёт группа; вместо `CustomTouchableOpacity` — `PressableScale` с `PRESS_SCALE.ROW`. Удалены мёртвые импорты `COLORS` / `EColorThemes` / `colorTheme`.
- Переход на детали **вынесен из entity в feature** (`architecture.md`, правило 1): `HistoryItem` принимает `onPress`, `router.navigate` живёт в `MapHistoryItems`.
- `entities/History/lib/getHistorySignColor.ts` — цвет по знаку суммы одной функцией, а не двумя тернарниками (нужен и списку, и деталям).
- `entities/History/config/constants/HISTORY_TYPE_ICONS.ts` — маппинг типа операции в иконку набора «21 Век».
- `MapHistoryItems` — `ListGroup` + `.map()` вместо `FlashList` со `scrollEnabled={false}` внутри чужого `ScrollView` (в этом режиме его измерения не работают), `key={item.id}` вместо `key={item.date}`. Пустое состояние — `CenteredState`.
- `GetHistoryPieChart` — `GlassCard` вместо карточки `BACKGROUND.Tertiary`/`padding 30`, внутри `DonutChart` с суммой `num20` и подписью «за период» в центре, ниже легенда новым `entities/History/HistoryChartLegendItem`. Починен `useMemo` с пустым массивом зависимостей при использовании `COLORS` — стили карточки не пересчитывались при смене темы. В маппинг добавлен `PAY_BALANCE`, которого в старом `switch` не было вовсе (сегмент пополнений молча терялся).
- `GetHistoryPieChartWithoutData` — вместо `blured.png` и белой плашки `rgba(255,255,255,0.8)` (в тёмной теме она была сломана) пустое кольцо с подписью: блок не прыгает по высоте при смене периода.
- Удалены `shared/CustomPieChart` (4 файла) и `blured.png`.

### 5. Детали операции

`HistoryDetailsWidget` по `dc.html:315–324`: центрированная шапка «`StatusPill` → сумма `h2` цветом знака → дата `caption12`» и одна `ListGroup level="secondary"` из `ListRow`.

Набор строк даёт чистая функция `lib/buildDetailsRows(type, data)`. Она же деградирует на неизвестном типе пустым массивом — типов у бэка может стать больше, чем в `EHistoryItemType`.

Схлопнуты и удалены: `features/History/OpenHistoryDetails` целиком (3 тела + 3 скелетона + барель, в котором `BuyOnCashSkeleton` экспортировался дважды, а `PayBalanceSkeleton` не экспортировался вовсе — из-за чего виджет импортировал его вглубь), `entities/History/HistoryDetailsTitle`, `HistoryDetailsBuyOnCashItem`, `HistoryDetailsTransferBalanceItem`. Заодно ушли `switch` с проваливающимися ветками (без `return` при `!data`) и оба `@ts-ignore`; `params.type` приводится к енаму в одном месте.

`ErrorWhileFetchingForm` (18 потребителей) не тронут — обе ветки истории перешли на `CenteredState variant="error"` с действием «Повторить».

### 6. Композиция и слои

`HistoryWidget` больше не импортирует `layouts/` — layout надевает `HistoryScreen`, как в остальных 22 экранах. Убран `ScreenTitle`, дублировавший заголовок шапки. Тернарная лесенка заменена ранними `return`, пустой `styles.container` со `StyleSheet.create` на уровне модуля удалён.

Событие «долистали до конца» передаётся через стор слайса `widgets/HistoryWidget/model/HistoryStore.ts` (счётчик `loadMoreTick` + `requestLoadMore`): скроллом владеет layout на слое `screens`, а страницы грузит виджет — прокидывать колбэк пропами пришлось бы через оба слоя. Экран остаётся тонким, направление импортов — строго вниз.

Собственный скроллящийся список с `onEndReached` не заводили: `InternalPagesLayout` оборачивает детей в `KeyboardAwareScrollView` для всех внутренних экранов, и `hideScroll` этого не отменяет — вложенный список остался бы без ограниченной высоты.

### 7. Баги запросов

1. **4 запроса вместо 2 на старте** — `useEffect(…, [])` и `useEffect(…, [dates])` оба отрабатывали на монтировании. Остался один эффект: он же и есть первая загрузка.
2. **Дубль первой страницы** — при долистывании запрашивалась текущая, уже загруженная `page`, и только потом `setPage(prev + 1)`. Теперь запрашивается `page + 1`, а `page` растёт только после успешного ответа, в `afterDataCallback`.
3. `page` сбрасывается в 1 при смене периода — иначе новый период грузился со старым смещением.

### 8. Скелетоны

`HistoryWidgetSkeleton` переверстан под новую раскладку (два поля 44 → кольцо 160 → легенда → 5 строк по 58) и переведён на барель `shared/Skeleton` вместо импорта вглубь. Три скелетона деталей схлопнуты в один `HistoryDetailsWidgetSkeleton`; вместе со старыми файлами ушёл `Skeleton width={100} height={40}` без `SIZES.PX`.

## Расхождения макета и API

1. **Пончик в макете ни на чём не основан.** Проценты `62% / 84%` вбиты в CSS, число «8 540» — литерал; сумма операций списка даёт 1 180. Что означают сектора, не подписано. Реализовано по данным `history/chart/`: сегмент на каждый тип операции.
2. **Легенды в макете нет.** Три безымянных сектора ещё читаются, пять — нет, поэтому под кольцом добавлена компактная легенда «точка + подпись + сумма». Это осознанное отступление от макета.
3. **Иконки под `BUY_ON_CASH` в наборе «21 Век» нет** — макет для покупок на кассе иконку не рисует. Временно взята `home_prices` (ценник с главной). Нужна отдельная иконка от дизайнера.
4. **Два поля даты в макете открывают нативный date-picker**, которого в RN нет. Оба поля открывают одну модалку-диапазон `RangePickerModal`. Как следствие поля не редактируются по отдельности.
5. **Фильтр по датам в прототипе не работает** — `onDateFrom/onDateTo` только пишут в state, список статичен. В приложении смена периода перезапрашивает и список, и сводку.
6. **Кнопки сброса периода в макете нет.** Без неё нельзя вернуться к «за всё время», поэтому под полями остаётся `LinkButton` «Сбросить период», видимый только когда период выбран.
7. **Данные макета выдуманы**: 4 операции, валюта ₽, «Банк: Тинькофф», «Способ: СБП» — российские платёжные реалии в приложении азербайджанской сети. Верстали под реальный контракт `history/journal/` и `history/detail/`; суммы отображаются в бонусах через `BonusIcon`.
8. **Разделитель у последней строки** в макете остаётся у обеих групп — судя по остальным экранам (профиль, FAQ, настройки), это недосмотр прототипа. Сделано «как везде»: последняя строка без разделителя.
9. **Пагинации в макете нет** — в приложении она есть и осталась.
10. **Статусов операции** (возврат, отмена, «в обработке») в макете нет и в API их нет: в пилюлю подставляется заголовок операции, тон — по знаку суммы.

### Что осталось проверить руками на устройстве

Автотестов в проекте нет, дев-билд отсюда не запускался — всё ниже нужно пройти вручную:

1. Главная → плитка «История»; профиль → «История операций».
2. Выбор периода, сброс периода, пустой период.
3. Долистывание до конца — **первая страница не должна дублироваться**, вторая должна догружаться один раз.
4. Тап по строке → детали для **всех пяти** типов операций (пополнение, перевод, налив, кофе, касса).
5. Ошибка сети (авиарежим) на обоих экранах → «Повторить».
6. **Обе темы** (`features/ChangeColorTheme`): сквозь отверстие кольца должны просвечивать амбиентные блобы, легенда должна читаться в светлой теме.
7. Android без блюра — поля периода и группы должны падать на `GLASS.Solid*`, а не выглядеть прозрачными.
