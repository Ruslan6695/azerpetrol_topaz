# feature/redesign_histroy — Выход с экрана «Идёт налив»

## Описание задачи

Шаг `fuelling` роута `/fuelLoading` оказался единственным экраном приложения,
с которого нет ни одного выхода. Если колонка не возвращает статус `complete`,
пользователь заперт на крутящемся кольце: свайп-возврат выключен на роуте,
аппаратная кнопка Android заглушена, круга «←» в шапке нет, кнопок нет. Отдать
управление обратно может только сам поллинг — переводом в шаг `end` или `error`.

Проблема в том, что статусы `idle` и `halted` **не терминальные**: поллинг на
них не останавливается, а просто меняет подпись под кольцом. Молчащая колонка
держит человека до дедлайна в 10 минут, и единственный выход всё это время —
полностью убить приложение. Именно с этим пришёл пользователь.

Задача: снять все три замка и вернуть шагу налива обычное поведение экрана —
стрелка, свайп, системная кнопка «назад».

---

## Что было сделано

### 1. Круг «←» в шапке шага налива

Стрелка не рисовалась, потому что `StepHeader` показывает её только при наличии
пропа `onBack` — так и задумано, «шаг, с которого уходить некуда»:

```tsx
/** Без обработчика круг «←» не рисуется — шаг, с которого уходить некуда */
onBack?: () => void
```

Теперь шаг налива этот проп передаёт и получает ровно ту же стеклянную кнопку,
что стоит на шаге «Запуск налива» — ничего нового не нарисовано:

```tsx
<StepHeader title="Идёт налив" onBack={handleGoBack} />
```

Кнопка видна с первой секунды и уводит с экрана одним тапом, без подтверждения.

**Файл:** `src/widgets/FuelLoading/FuelLoadingFuellingWidget/ui/FuelLoadingFuellingWidget.tsx`

---

### 2. Свайп-возврат на роуте

В `src/app/_layout.tsx` у `fuelLoading/index` стоял явный запрет — снят:

```diff
  options={{
      headerShown: false,
-     // Свайп назад увёл бы с идущего налива:
-     // выход с этого роута только кнопками шага.
-     gestureEnabled: false,
      // Налив перехватывает экран целиком, поэтому
      // проявляется, а не приезжает сбоку как «ещё одна страница».
      animation: 'fade',
      animationDuration: 300,
  }}
```

Документация react-native-screens 4.16 (сверено через context7) уточняет две
вещи, важные для этой правки:

- `gestureEnabled` — **проп только для iOS**. На Android свайп-возврата в
  нативном стеке нет вообще, там за возврат отвечает системная кнопка/жест,
  поэтому одного снятия запрета было бы мало (см. пункт 3).
- `animation: 'fade'` жест **не отключает**. В `RNSScreenStack` любая анимация,
  кроме `Default` и `Flip`, считается кастомной, и pop идёт через
  `RNSScreenStackAnimator` — интерактивный свайп при этом работает как
  percent-driven переход. Менять анимацию ради жеста не понадобилось, фейд
  из макета сохранён.

**Файл:** `src/app/_layout.tsx`

---

### 3. Аппаратная кнопка Android

Эффект, который глушил системную кнопку, удалён целиком:

```tsx
// удалено
useEffect(() => {
    const subscription = BackHandler.addEventListener('hardwareBackPress', () => true)
    return () => subscription.remove()
}, [])
```

Своего обработчика теперь нет — кнопка и системный жест «назад» просто
выталкивают роут из стека штатным образом. Импорты `BackHandler` и `useEffect`
из файла ушли вместе с ним.

---

### 4. Куда ведёт выход

`router.back()` — тот же выход, что «Отмена» на шаге запуска:

```tsx
const handleGoBack = useCallback(() => {
    router.back()
}, [router])
```

Все три способа выхода (стрелка, свайп, системная кнопка) приводят в одно и то
же место — на **выбор литров**, а не на главную и не на первый шаг «Заправка».
Работает это потому, что роут `/fuel` остался в стеке под `/fuelLoading`
(переход шёл через `router.navigate`), а процесс `Fuel` держит свой шаг в
`useState` — `road === 'selectLiters'` переживает возврат вместе с выбранными
АЗС, колонкой и топливом.

`clearState()` намеренно не вызывается — на шаге запуска отмена его тоже не
вызывает, выбор должен пережить возврат.

Останавливать поллинг вручную не потребовалось: при навигации виджет
размонтируется, эффект `useFuellingPolling` возвращает `stop`, интервал
гасится, а `cancelledRef` отсекает ответ, оставшийся в полёте.

## Что осталось как было — намеренно

| Что | Почему не тронуто |
|-----|-------------------|
| `DEADLINE_MS = 10 * 60 * 1000` в `useFuellingPolling` | Логику таймаута решено в этой правке не менять |
| `gestureEnabled: false` у роута `success/index` | Другой экран, к задаче отношения не имеет |
| Навигация прямо из виджета | `architecture.md` просит выносить переходы в `features/`, но все четыре виджета ветки `FuelLoading` (`Start`, `End`, `Error`, `Fuelling`) ходят в `router` напрямую. Отдельная фича ради одной стрелки разошлась бы с веткой |

Подтверждение выхода (`ConfirmDialog`) в промежуточной версии было, но по
решению заказчика убрано: выход должен быть в один тап.

## Расхождение, требующее ответа бэкенда

Уход с экрана **не отменяет сессию налива** — закрыть её нечем, эндпоинта
отмены не существует, в API есть только `fuelling/start/` и `fuelling/status/`.
Отсюда два следствия, которые стоит проговорить с бэкендом:

1. Если пользователь снова пройдёт выбор литров и нажмёт «Запустить колонку»,
   уйдёт второй `fuelling/start/` при живой сессии. Как поведёт себя колонка,
   из клиента не видно.
2. Вернуться к наблюдению за уже идущим наливом после выхода нельзя — экран
   поднимается только через шаг «Запуск налива».

Побочно всплыло смежное место: `handleRetry` в `proccesses/FuelLoading` заново
монтирует виджет, из-за чего `DEADLINE_MS` отсчитывается с нуля, и общий таймаут
можно продлевать неограниченно. Отдельной задачи под это не заводилось.

  отклонения по навигации из виджета (см. таблицу выше).

  запускается) и прогон сценария: круг «←» уводит на выбор литров с сохранённым
  выбором → на iOS работает свайп от левого края → на Android системная кнопка
  и жест «назад» делают то же самое → шаг «Запуск налива» не изменился.
  Обе темы тоже глазами не смотрели.
